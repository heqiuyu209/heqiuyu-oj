# 学习路线与验证方式

## 1. 需要掌握的知识

### 第一层：现有 HOJ

- Vue 2、Vue Router、Vuex、Axios；
- Spring Boot Controller、Service、Mapper；
- MySQL 表设计和 MyBatis-Plus；
- Redis、异步任务和缓存；
- Shiro/Token 鉴权；
- JudgeServer 与提交状态流转。

### 第二层：RAG

- 文档解析和清洗；
- 分块策略和重叠窗口；
- Embedding 与向量相似度；
- Qdrant payload 和过滤；
- 混合检索、重排和引用；
- Prompt 设计和上下文窗口；
- SSE 流式响应。

### 第三层：AI 产品工程

- 多供应商适配；
- Token、成本和限流；
- Prompt 注入与数据泄露防护；
- LLM 评测；
- 异步任务、重试、降级和观测。

### 第四层：学习分析和远程评测

- 行为事件建模；
- 可解释推荐；
- 知识点图谱；
- Codeforces 提交状态和限流；
- 分布式任务幂等。

## 2. 每个阶段的验证

### RAG

准备 20 个标准问题，每个问题标注正确文档和章节。验证召回是否包含目标片段，以及回答是否引用正确来源。

### AI 问答

准备题目教学测试集：概念题、思路题、代码错误题、恶意提示注入题、比赛禁用题。检查回答风格和权限结果。

### 学习工作台

使用脱敏的历史提交数据，手工确认薄弱点和推荐理由是否符合教练判断。先验证可解释性，再追求复杂模型。

### CF VJ

使用专用账号和少量公开题目，测试提交成功、编译失败、答案错误、超时、网络失败、重复提交和远程平台不可用。

## 3. 最小可交付版本

第一版不要追求所有功能同时上线，建议定义为：

- 管理员上传 Markdown、TXT、PDF；
- RAG 完成检索和引用；
- 普通题目页面提供分层提示；
- 比赛期间后端硬禁用 AI；
- 工作台展示基础薄弱点、计划和推荐；
- 支持 DeepSeek、OpenAI、Claude 中至少两个；
- CF 完成最小异步提交和结果轮询。

视频转写、复杂学习推荐、混合检索和完整 VJ 排名可以作为第二阶段，避免第一版的故障面过大。

## 4. 可考虑的创新点

### 教学状态机

记录学生目前处于“读题、建模、设计算法、证明、实现、调试、复盘”哪个阶段，AI 根据阶段给不同问题，而不是每次都重新讲一遍题。

### 知识点图谱

把题目标签、算法概念、前置知识和训练顺序组成图。工作台可以解释“为什么先学这个，再学那个”。

### 反作弊式学习反馈

不把“看过题解”当作“掌握”。通过延迟复测、变式题和让学生解释复杂度，检测是否真正理解。

### 代码演进分析

比较用户多次提交的代码变化，展示从 WA 到 AC 的错误修复路径，形成个人调试档案。

### 教练协同

教练可以查看集训队整体薄弱点、推荐公共训练和审核知识库资料，但不能默认查看学生私有 AI 对话和完整代码。

### 赛后复盘模式

比赛结束后自动生成个人复盘：做题顺序、卡题时间、错误类型、未尝试题目和下一周训练建议。复盘不改变正式比赛排名。
