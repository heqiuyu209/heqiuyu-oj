# AI 学习工作台实现文档

## 1. 与 AI 问答的区别

学习工作台不是另一个聊天窗口，而是“数据驱动的学习控制台”：

- 问答页面回答用户现在的问题；
- 工作台告诉用户接下来学什么、为什么学、完成得怎么样。

AI 可以解释计划和生成复习内容，但核心统计和推荐候选必须能够被后端复现。

## 2. 页面组成

### 首页概览

- 当前学习目标；
- 今日计划；
- 本周完成度；
- 最近薄弱点；
- 推荐题目；
- 连续学习和复习提醒。

### 学习计划

用户输入目标，例如“准备 ICPC 区域赛”“两周补强图论”。系统生成：

- 时间范围；
- 知识点顺序；
- 每日学习任务；
- 题目和资料；
- 阶段性复盘点。

计划必须允许用户编辑，不能由 AI 单方面锁死。

### 薄弱点分析

按知识点展示：

- 尝试次数；
- 通过次数；
- 首次通过耗时；
- 最近一次表现；
- 常见错误；
- 难度分布；
- 建议复习资料和练习题。

### 题目推荐

每个推荐都应显示原因，例如：

- “用于巩固你最近三次提交中出现的二分边界问题”；
- “难度比你最近通过的题目高一级”；
- “用于复习七天前学过但近期未练习的最短路”。

## 3. 学习事件

建议记录以下事件：

- 查看题目；
- 开始/完成训练；
- 提交代码；
- 通过或失败；
- 查看题解；
- 使用 AI 提示；
- 完成计划项；
- 用户标记“已掌握/仍不会”；
- 用户评价推荐。

事件用于统计和实验，不要仅依赖页面停留时间判断掌握度。

## 4. 薄弱点模型

第一版可以采用可解释的规则：

```text
weakness_score
 = 失败率 × 0.4
 + 最近失败权重 × 0.3
 + 重复错误权重 × 0.2
 + 长时间未复习权重 × 0.1
```

分数只是排序依据，不要直接宣称“你不会某知识点”。界面应使用“建议重点复习”之类的表达，并允许用户纠正标签。

错误分类可以从评测状态和代码分析开始：

- WA：样例/边界/状态转移/初始化；
- TLE：复杂度、重复计算、IO；
- MLE：数据规模、容器、缓存；
- RE：越界、空值、递归深度、类型；
- CE：语法、类型、头文件、语言版本。

## 5. 题目推荐策略

推荐候选先由规则筛选，再由 AI 解释：

1. 过滤用户无权访问和比赛中的题目；
2. 过滤已经熟练解决的题目；
3. 匹配薄弱知识点和学习目标；
4. 控制难度梯度；
5. 保留一定比例的复习题和迁移题；
6. 去除最近推荐过的重复题；
7. 根据用户反馈重新排序。

不要第一版就使用黑盒推荐模型。先做可解释规则，积累事件数据后再考虑协同过滤或学习排序。

## 6. 关键指标

- 计划完成率；
- 推荐题目开始率和通过率；
- 推荐后同类错误是否下降；
- 用户主动修改计划的比例；
- AI 使用次数与实际做题结果的关系。

这些指标用于改进系统，不应直接作为竞赛排名依据。
