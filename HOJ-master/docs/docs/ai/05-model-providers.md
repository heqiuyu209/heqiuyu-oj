# 多模型与多供应商实现文档

## 1. 统一抽象

HOJ 不应在业务代码中到处写 DeepSeek、OpenAI 或 Claude 的判断。建立统一接口：

```text
ChatModel
  chat(messages, options) -> Answer
  stream(messages, options) -> Stream<Delta>
  count_tokens(messages) -> UsageEstimate
```

供应商适配器负责把统一消息格式转换成具体 API 格式，并把异常转换成统一错误：认证失败、限流、超时、内容过滤、服务不可用。

## 2. 首批供应商

### DeepSeek

优先使用 OpenAI 兼容适配器。适合成本较低的普通教学问答和总结任务。

### OpenAI

同样走兼容适配器，但模型名称、上下文长度和能力由配置决定。不要在代码中写死具体模型名称。

### Claude

保留原生 Anthropic 适配器，因为 system message、流式事件和响应格式与 OpenAI 兼容接口不同。

## 3. 路由策略

按照用途选择模型，而不是所有请求使用同一个模型：

| 用途 | 默认策略 |
|---|---|
| 概念问答 | 成本和速度优先 |
| 题目教学 | 推理和教学质量优先 |
| 代码分析 | 上下文长度和稳定性优先 |
| 学习计划总结 | 成本和结构化输出优先 |
| 管理员测试 | 指定模型或回退模型 |

第一版只需静态配置路由，后续再做动态成本和健康度路由。

## 4. 配置原则

- API Key 只保存在服务端环境变量或密钥管理系统；
- 数据库只保存密钥引用，不保存明文；
- 日志禁止打印 Authorization、完整 Prompt、完整代码；
- 每个模型配置超时、最大输出、温度、重试次数和限流；
- 记录供应商、模型、Token 和耗时，方便成本核算。

## 5. 失败处理

```text
主模型超时/限流
 → 重试有限次数
 → 切换同用途回退模型
 → 仍失败则返回可理解的降级提示
```

不能在模型失败时自动切换到会泄露比赛内容的模型或绕过权限检查。比赛禁用判断必须发生在模型路由之前。
