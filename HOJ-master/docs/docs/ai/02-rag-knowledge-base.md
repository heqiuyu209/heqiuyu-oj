## 1. 知识来源

### HOJ 内部数据

- 题目：标题、描述、输入、输出、样例、限制、标签、难度。
- 训练：训练说明、题目列表、知识点和推荐顺序。
- 讨论：只同步公开且允许进入知识库的内容；不能把未经审核的讨论直接当作标准答案。
- 提交：默认只作为用户个人代码分析上下文，不作为公共知识库内容。
- 文档：管理员上传的算法讲义、课程资料、规范和内部总结。

### 文件类型

| 类型 | 入库方式 | 重要元数据 |
|---|---|---|
| Markdown | 解析标题层级和正文 | 文件、章节、主题 |
| TXT | 按段落和语言切片 | 文件、主题 |
| PDF | 提取文字；扫描件可选 OCR | 文件、页码、章节 |
| 视频 | 抽取音频并 ASR 转写 | 视频、讲者、开始/结束时间 |
| 代码 | 可选，按语言和函数切片 | 文件、语言、题目/课程 |

视频本身不直接向量化。正确流程是：视频 → 音频 → 语音识别 → 带时间戳的文本 → 切片 → Embedding。回答引用视频时应显示时间点，方便学生回看。

## 2. 文档生命周期

```text
UPLOADED → PARSING → CHUNKING → EMBEDDING → INDEXED
                         ↘ FAILED
```

同一个文档应通过内容 Hash 幂等。重新上传相同内容不应生成重复向量；内容变化则创建新版本，旧版本进入归档或删除状态。

## 3. 建议的数据对象

### Document

- `id`
- `name`
- `source_type`：HOJ_PROBLEM、TRAINING、UPLOAD、VIDEO_TRANSCRIPT 等
- `source_ref_id`：关联题目或训练 ID
- `visibility`：PUBLIC、TEAM、PRIVATE、CONTEST、ADMIN
- `status`
- `content_hash`
- `version`
- `created_by`

### Chunk

- `id`
- `document_id`
- `version`
- `content`
- `chunk_index`
- `heading_path`
- `page_number`
- `start_time_ms`、`end_time_ms`
- `problem_id`
- `tags`
- `visibility`
- `embedding_model`

向量库中的 payload 必须保留这些过滤字段。不要只保存一段没有来源的纯文本，否则无法做权限控制和引用展示。

## 4. 检索策略

第一版可以使用向量检索，但算法题通常包含关键词、符号和代码，后续应升级为：

```text
HOJ 当前身份、比赛策略、可访问的文档版本
       → 带权限与版本过滤的关键词/BM25 + 向量检索
       → 合并候选
       → 再次校验资料权限与引用
       → 重排
       → 去重和上下文压缩
       → 交给模型
```

查询时要加入结构化过滤：

- 当前题目 ID；
- 题目标签和训练 ID；
- 用户可见范围；
- 是否处于比赛；
- 文档类型和语言。

## 5. RAG 回答要求

系统提示词应要求模型：

1. 只把检索内容当作内部资料依据；
2. 区分“资料明确说明”和“模型根据算法知识推断”；
3. 不伪造题目、章节、页码或代码运行结果；
4. 优先教学和提问，引导学生推导；
5. 返回引用 ID，前端再渲染为可点击来源；
6. 资料不足时明确说“当前知识库没有足够依据”。

模型可以联网并不等于 RAG 可以联网。产品上要区分：

- **内部知识回答**：来自 RAG，可展示来源；
- **模型通用知识回答**：来自模型，可标记为非内部资料；
- **联网结果**：如果将来开放，必须单独标记来源和开关。

## 6. 复用 Learning OS 时的学习重点

建议按以下顺序阅读现有代码：

1. `domain/interfaces.py`：理解抽象接口；
2. `domain/models.py`：理解 Document、Chunk 和 SearchResult；
3. `application/ingest_pipeline.py`：理解入库编排；
4. `infrastructure/container.py`：理解依赖注入和插件注册；
5. `infrastructure/parsers`、`chunkers`、`embedders`、`vector_stores`；
6. `web/app.py`：理解当前问答原型与正式服务的差距。

不要直接把 Streamlit 页面当作生产 API。它适合验证检索质量，正式系统应增加 HTTP API、鉴权、任务队列和持久化。

## 7. RAG 验收指标

- 召回正确章节的比例；
- 引用来源覆盖率；
- 无相关资料时的正确拒答率；
- 权限过滤零泄露；
- 入库任务可重试、可观测；
- 同一文档重复导入不重复计数。

## 8. 2026-10-18 原型核验与接入顺序（历史核验与设计）

### 已核验的代码边界

`D:\learning-OS-RAG\src\learning_os` 有领域接口、Markdown 解析、递归切片、Embedding、Qdrant、向量检索和模型适配器；`cli/main.py` 提供 search / ask，`web/app.py` 是 Streamlit 页面。解析器注册表目前只注册 markdown；安装依赖出现 PyMuPDF、模型字段出现 page，都不证明已实现 PDF / TXT / OCR。未运行原型测试、Embedding 模型下载或向量服务，本轮不声明其运行验收通过。

`domain/interfaces.py` 的 MetadataFilter 只有 document_id / source / source_type / subject / topic / language / chapter / tags，未包含 HOJ UID、资料范围或版本访问权；Qdrant 当前过滤列表为 AND，不能直接拿它表达多个允许文档版本的 OR。`domain/models.py` / `markdown_parser.py` 以内容哈希标识文档，`qdrant_store.py` 按 source 替换旧向量；相同内容或同名 source 在多用户系统里不能因此合并归属。直接开放这些原型入口不能建立 HOJ 的权限隔离。

### 复用与边界

- HOJ 保留登录身份、正式 / 虚拟参赛策略、资料权限、文档状态与版本，MySQL 为事实源。浏览器只访问 HOJ，Python 检索服务位于内部网络，不接受浏览器 Cookie、客户端自报 UID 或未经服务端授权的 scope。
- 先复用解析、切片和向量存储接口；增加资料 / 版本适配层，服务端生成 documentId、versionId、chunkId，内容 hash 只负责该资料范围内的幂等。向量主键必须包含资料和版本命名空间，删除 / 替换也限定资料版本，避免按文件名跨用户删除。
- Python 首版只做入库与检索，HOJ 继续通过现有用户模型设置生成回答。模型 Key 不交给检索服务或浏览器；Embedding 配置与用户聊天模型分开。内部调用需固定服务身份、短有效请求授权与请求 ID，来源文档和模型输出均不能改变可见范围。
- HOJ 在检索前解析允许的已发布 document/version 集合，内部服务强制过滤；候选返回后 HOJ 再核对当前权限、版本和引用，失效时丢弃并补检索。空授权集合直接拒绝 / 返回无资料，不退化为全库检索；不得先把越权候选交给重排器或外部模型。缓存键包含授权 / 版本修订信息，不能复用其他用户的回答缓存。

### 第一个最小流程

管理员上传一份 Markdown → HOJ 创建 document/version 和持久入库任务 → 内部 worker 在隔离目录解析、切片、索引 → 全部成功后发布该版本 → 已授权用户询问 → 权限过滤检索 → HOJ 现有模型生成带引用回答。上传不等待 Embedding；任务保存实际阶段、失败原因和重试状态，已发布旧版本在新版本失败时继续可用。删除先撤销可见性，再幂等清理对应版本索引；延迟任务与旧回调不能重新发布已删除版本。

内部检索请求草案包含 requestId、授权后的 document/version 引用、query、topK、deadline，不携带用户模型 Key；结果包含 documentId、versionId、chunkId、title、headingPath、可选 page / 时间戳、excerpt、检索分值和 contentHash。HOJ 校验并生成可访问的引用链接，不把内部文件路径或仅由模型生成的 citation ID 当作来源。API 名称与上传 / 检索限额尚未定案，不能据本文认为服务已实现。

### 验收与后续

首轮须覆盖：不同用户上传同字节 / 同文件名保持权限隔离；同一资料重复导入幂等；更新失败保留旧版；撤销权限、删除、旧任务回调与迟到响应均不可见；空权限集不访问全库；比赛限制在检索前和模型结果返回前都生效；无相关资料明确表示依据不足；每条引用可定位到允许的原版本 / 章节。采用合成模型和小型受控索引先验证契约，再使用固定算法讲义验证真实召回与引用，分别记录两类证据。

下一步先实现上述内部身份 / 文档版本 / 引用最小契约，再扩展 TXT、文本 PDF、OCR 和视频；不同时引入多 Agent 编排。推荐功能先由 HOJ 筛出可见、未做、来源去重和难度合适的真实题目，模型解释理由；各平台 Rating 分开保留，缺少样本不补造能力结论。上传角色、Embedding 供应商与外发资料策略在接入前确认，不因原型已有模型适配器就默认允许发送全部资料。

## 9. 2026-10-19 内部索引接口（进行中，尚未接入页面）

### 当前代码

`D:\learning-OS-RAG\src\learning_os\hoj` 新增独立的 FastAPI 内部适配器，复用 Markdown 解析、递归切片、本地 BGE-M3 和 Qdrant 客户端。支持 Markdown / 纯文本入库、版本范围检索和指定版本删除；不复用个人 CLI 的 collection、按 source 替换或 LLM 适配器，不读取原型 `.env`。服务构造只接受已安装的本地模型目录，强制离线模式。

`DataBackup/.../manager/oj/ai/RagServiceClient.java` 为固定运维配置的内部客户端；默认配置为空，不影响既有助教。`hoj.rag.url` 为内部服务 origin，`hoj.rag.shared-key-file` 指向服务共享凭据文件。凭据与用户模型 Key 分离。客户端不接受浏览器自报范围，不跟随重定向、不自动重投递；先校验允许版本，再核对返回片段的版本、哈希、数量与字段边界。

资料版本的索引主键包括命名空间、documentId、version、片段序号与片段哈希。相同字节不合并不同资料 / 版本；相同版本重试幂等，正文、标题或格式不能原地修改。SQLite manifest 仅记录内部索引的 WRITING / READY / DELETED，不能代替 HOJ 的发布状态及 ACL。分批写入全部完成后才 READY；失败新版本不影响旧版本；删除先保留持久撤销标记，再清理向量，迟到入库不得复活。检索使用明确授权的完整三元组 OR；空集合不调用 Embedding 或全库查询。

### 已定的内部协议

| POST 路径 | 请求 | 返回 |
| --- | --- | --- |
| `/internal/v1/ingest` | documentId、version、contentHash、title、format、content | INDEXED 回执与片段数 |
| `/internal/v1/retrieve` | query、allowedVersions 三元组列表、topK | items：版本、片段 ID / 哈希 / 序号、标题、章节、片段、cosine score |
| `/internal/v1/delete` | documentId、version、contentHash | DELETED 回执 |

三元组仅含 documentId（32 位小写 hex）、version（正整数）、contentHash（原始 UTF-8 正文 SHA-256）；标题最长 200 字、正文 200,000 字、提问 2,000 字，授权版本最多 500 个，topK 为 1–10，HTTP 请求上限 1 MiB，响应上限 256 KiB。长度按 Unicode 码点计算。Markdown 引用保留实际 ATX 标题路径，代码围栏中的 `#` 不当作标题；YAML front matter 不参与身份或权限。

内部鉴权使用随机 32 字节共享凭据，以及 X-HOJ-Request-Id / Deadline / Signature。签名绑定协议版本、POST、路径、请求 ID、绝对截止毫秒及原始请求体哈希；最长有效 120 秒，SQLite 保存有效期内的防重放记录。新 HTTP 重试使用新请求 ID，入库仍按资料版本幂等。完整启动及验证步骤见 RAG 仓库 `docs/hoj-integration.md`。

## 10. HOJ 资料、发布与服务端问答（后端已本地部署，页面待接入）

### 资料与权限

`KnowledgeManager` 使用 MySQL knowledge_document / knowledge_version / knowledge_command / knowledge_job。仅 root / admin 可维护，problem_admin、团队管理员及普通用户不可上传或改动。当前可见范围为 PUBLIC（登录且拥有 submit 权限）和 ADMIN（root / admin）；TEAM / PRIVATE / CONTEST 范围没有开放，不把维护角色与可见范围混同。

管理员上传 Markdown / 文本正文后创建待入库版本，服务器生成资料 ID、规范化换行、计算内容哈希并保存幂等请求；客户端不能自报已索引、已发布、内容哈希或允许版本集合。相同内容 / 标题 / 格式的重复上传不新建版本；后续新版本不覆盖旧正文。编辑、发布、撤回、可见性和重试使用 expectedRevision，冲突返回 409。索引完成不自动发布，管理员需显式选择 INDEXED 版本；可回退发布旧的已索引版本。原文入口只向用户开放当前已发布版本，旧引用在更新 / 撤回后失效。

### 持久任务

`KnowledgeJobManager` 使用独立后台线程，不阻塞 Spring 的比赛截止调度。领取采用原子 UPDATE 的当前读取与 180 秒租约，不在 HTTP 中持有数据库锁；回执使用文档 → 任务的固定锁顺序，并校验当前 token / 截止 / 逻辑删除状态。重启或进程失败后可回收过期任务；旧回执不能覆盖新租约。入库失败自动退避，三次后标为 FAILED，管理员可重试；已索引版本重建时仍保留发布状态。删除先撤销发布、标记版本已删除、取消入库，再持久保存逐版本清理任务；清理失败继续退避重试，不能恢复可见性。

仅保存受控失败码，不保存上游异常正文、片段或凭据。这里提供 QUEUED / RUNNING / DONE / FAILED 等实际任务状态，尚无解析 / 切片 / Embedding 的逐阶段进度回调。逻辑删除保留数据库正文以支持审计，不等于物理清除。

### 检索与模型外发

用户先获取已发布目录，再按问题检索，可指定最多 100 个资料 ID；服务端与当前可见已发布版本取交集，最多向内部索引发送 500 个完整三元组。超过范围需用户选择资料，不能悄悄截断全库。空集合不调用内部服务。检索结果检查当前发布版本、文档 revision、标题、内容哈希和片段是否确实存在于 MySQL 原文；来源 URL 与 K1 等引用 ID 由 HOJ 生成。

`allowModelExcerpts` 默认为 false。未勾选的 answer 请求执行纯检索，不读取用户模型设置、不解密 Key、不调用供应商；勾选后才用本人设置发送当前问题和命中的可见片段，不附带聊天历史、完整文档或能力画像。首版只核验已提供的引用 ID；2026-10-21 后续实现升级为每段说明都附带当前片段的连续原文摘录，见第 16 节。实际模型质量仍需后续评测，不凭 ID 或摘录匹配推断内容正确。

目录、原文、检索和问答均复用服务端 AiAccessGuard；正式或持久虚拟参赛期间禁用，与用户当前页面无关。检索前后及模型调用前后重新检查参赛、可见性与版本；撤回或更新发生在等待期间时，响应被丢弃并返回 409。纯检索每用户两秒冷却，模型问答共用原助教的并发与每分钟限制。纯检索无需配置模型；内部服务未配置但确有待检索资料时明确返回 503，不把普通模型回答冒充知识库结果。

Markdown 资料原文和回答段落使用独立 MarkdownIt 15.0.3 解析器，支持 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`，包括求和、分式和矩阵。行内代码、围栏 / 缩进代码不作公式解析；TXT、PDF 提取页和回答展开的连续摘录仍按字面显示。标题携带转义后的原始文本用于引用路径匹配，不以 KaTeX 添加的 MathML 文本替换服务端标题身份。长公式在卡片内横向滚动，短公式保留足够的下标余量。

公式 `trust=false`，不允许公式创建链接、图片或 HTML。每个表达式最多 4096 字符，文档最多 256 个表达式 / 32768 个公式输入字符；额外限制括号深度 64、展开 500 次、尺寸 20 em。异常或超过限制的公式显示转义原文，后续公式和正文继续显示。宏只在一次文档渲染内共享，每次渲染新建无原型宏表，不跨资料保存。普通正文链接仅在原文页启用，仍经过 Markdown URL 校验并加新窗口隔离；回答正文没有活动链接。

KaTeX 固定为 0.18.2，旧插件通过 npm override 使用同版。旧版本的展开限制绕过和继承属性问题分别见 [官方展开安全通告](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-64fm-8hw2-v72w) 和 [官方继承属性安全通告](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7)，配置依据见 [KaTeX options](https://katex.org/docs/options.html)。默认 CDN 生产构建仍将 KaTeX / CSS / 字体打包到本站，后台 Editor 不再加载其内置旧版 KaTeX CDN；其他 CDN 策略沿用。新 entities 源码的数字分隔符由 Babel 显式转译以兼容 Webpack 4。

`npm run test:knowledge-render` 是纯渲染 / 资源限制回归，Node 22 容器安装与生产构建单独核对；浏览器沿用 knowledge-browser.cjs，验证原文、回答、引用标题、字面摘录、TXT、手机深色和既有 PDF / 视频行为。API / 回答为受控样例，不调用本人模型，不替代真实模型的公式正确性、语义支持或 OCR / ASR 识别质量验收；具体结果 / 失败记录与本地部署状态统一见 [TODO](TODO.md)。没有修改已存资料、检索向量或版本哈希。
